# VIGIA Phase B design implementation contract

Phase B may begin only after Phase A's backend, migration, security, deployment and full-suite gates pass. This document does not authorize visual work in Phase A.

The fixed screens and paths are the ten routes documented in `docs/internal/history/VIGIA_CANONICAL_API_CONTRACT.md`. The UI must use the locked dark navy/black, compact left-sidebar, red VIGIA shield and purple numbered-route-marker direction. It must remain responsive, accessible, restrained and understandable under degraded conditions.

Every visual value must come from the canonical operator API or an explicitly approved binary map/imagery proxy. No fake incidents, placeholder integrations, frontend provider calls, frontend evidence reasoning, dead controls, screenshot runtime backgrounds or horizontal-navigation redesign are permitted. A `LIVE` label must never be paired with a circular status dot.

The UI must preserve `READY`, `DEGRADED`, `UNAVAILABLE`, `UNKNOWN`, `BLOCKED` and `ABSTAINED` distinctions, knowledge time, source/provenance labels, rights exclusions and incident scope. It must never render missing numeric values as zero or transform a compatibility projection into authoritative truth. Consequential controls must display Proof Plane denial/step-up/unavailable states and must not bypass them.
