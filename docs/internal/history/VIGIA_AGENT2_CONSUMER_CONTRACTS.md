# VIGIA Agent 2 API and consumer contract inventory

All consumer contracts are backend-produced facts or decisions. The canonical authenticated HTTP boundaries are:

- `GET /api/v10/intelligence/incidents/:incidentId/snapshot`
- `GET /api/v10/intelligence/object-sets/:name`

Both require an authenticated actor, `read:incident_command`, and incident scope (or wildcard scope for global object sets). Compartment/capability rights are applied before returned objects are grouped. Repository consistency mismatch is an error, never a silent fallback.

File artifacts and internal services below are integration boundaries, not automatically public endpoints. Agent 1 must expose them through its canonical Operator API or an approved adapter without changing their semantics.

## Object-set query contract

`GET /api/v10/intelligence/object-sets/:name` returns `vigia.intelligence-object-page.v1`-style paged data or the indexed projection equivalent, with projection/consistency token, cursor, partial state and rights filtering. Supported sets include blocked-by-label/weather incidents, valid-label/progression/unstable geometry cohorts, contradictory hypotheses, missing independent corroboration, uncertified negatives, ranked acquisitions, broken lineage, rights-blocked products, stale materializations, and decisions awaiting authority. Unknown set names are errors.

## Frontend prohibition

The frontend must not calculate or infer:

- causal independence;
- source-family counts;
- evidence state or Evidence Debt;
- hypotheses or contradiction resolution;
- Decision Value or acquisition ordering;
- authority or continuous trust;
- source health/freshness classification;
- perimeter authority or revision admissibility;
- forecast applicability, calibration, or abstention;
- rights, compartment, licence, or redistribution decisions.

It may only render backend-delivered values, label missing/degraded/unavailable states, send authorized commands, and preserve provenance/knowledge-time context.
