# VIGIA 3.0 — Evidence Core release statement

## Before

VIGIA 2.0 established the evidence/remediation architecture, but several demo and UX seams undermined trust: demo observations could reuse identical pixels across locations, side panels could become one-way doors, seeded outcomes were not represented by audit events, field work could appear empty for the wrong role, consequence context was easy to lose, and observation quality was compressed into opaque scores.

## After

VIGIA 3.0 makes evidence integrity and operational ownership visible in the product:

- each rendered observation is geographically and temporally bound to its selected place;
- demo fixtures are distinct by territory and unmistakably synthetic;
- observation selection explains freshness, cloud, resolution, footprint coverage and rejected alternatives;
- operators can zoom, pan, compare, flicker and navigate observation history;
- experimental model findings are explicitly validation/demo-only and never self-promote into verified hazards;
- queue and details panels are always recoverable;
- navigation adapts to operator role;
- evidence requests expose ownership and lifecycle;
- field capture is offline-ready and daylight-capable;
- evidence, completion and re-observation workflows require actual media proof;
- consequence analysis remains gated by truth state and source freshness;
- every seeded proof loop has corresponding audit provenance;
- outcome metrics link back to evidence and methodology.

## Investor demonstration

Run `npm run dev:demo`, then demonstrate this closed loop:

1. Command — grouped work by Action now / Needs evidence / Watch / Done.
2. Observe — location-specific scene, evidence binding, timeline and optional experimental finding.
3. Assign verification — owner, requirements and due time.
4. Field Capture — acknowledge, start and submit attributable evidence.
5. Verify — accepted evidence can create a physical hazard; unsupported claims cannot.
6. Remediate — completion proof plus independent re-observation are required for closure.
7. Outcomes — before/action/after evidence and mapped-exposure methodology.
8. Audit — the same material transitions appear in the hash-chained ledger.
9. Incident Truth — public report versus independent support versus local verification.
10. Consequence Gate — only supported, non-stale incidents enter hypothetical screening unless a validated provider is configured.

## Safety boundary

VIGIA 3.0 is not a certified emergency service. Demo findings are not operational detectors. Public-source imagery and reports can be delayed, incomplete or unavailable. A missing sensor is never treated as negative evidence, and UI confidence may not exceed source evidence.
